# Biddex frontend

The whole cabinet of [app.biddex.online](https://app.biddex.online) (login, buyer, supplier and admin screens): plain HTML, CSS and JavaScript, no build step. `bid.html`, `verify.html`, `reset-password.html`, `privacy.html` and `terms.html` are separate pages. On every push to `main` the CI workflow (`.github/workflows/ci.yml`) runs the tests and only if they are green the `deploy` job publishes the site to GitHub Pages (Settings → Pages → Source: GitHub Actions). Only the files listed in `tools/build-site.js` are published (`node tools/build-site.js` builds the same folder `_site/` locally).

More about the project (architecture, API, process): `docs/PROJECT_CONTEXT.md` in the backend repository (`b2b-procurement-backend`).

## Which API a page talks to

`config.js` decides, from the address of the page:

| The page is opened at | API |
|---|---|
| `app.biddex.online`, `biddex.online`, any other real domain | **production** (always) |
| `http://localhost:…`, `http://127.0.0.1:…` | the **local backend**, `http://localhost:4000` |
| as above, with `?api=http://localhost:4010` | the local backend on that port (read only on localhost, only for a local address) |

So a page opened from your computer never touches production, and a link on the production domain cannot be redirected.

## Run everything locally (Windows, PowerShell)

You need Node.js 24 and both repositories next to each other, e.g. `C:\dev\b2b-procurement-backend` and `C:\dev\Biddex-frontend`. No PostgreSQL install and no Docker: the backend repository starts a local PostgreSQL for development.

### 1. The backend with a local database

```powershell
cd C:\dev\b2b-procurement-backend\b2b-backend
npm install
```

Create `.env` from the template (skip if you already have one) and check these lines. **Everything must point at your computer, never at production** (the production URL lives only in `.env.production`, which this setup never reads):

```
DATABASE_URL="postgresql://postgres:password@127.0.0.1:5432/biddex_dev"
JWT_SECRET=<any random text of 32+ characters>
RESEND_API_KEY=re_local_dummy_key
FRONTEND_URL=http://localhost:8080
CORS_ALLOW_LOCALHOST=1
```

`RESEND_API_KEY` must be a dummy: with it no e-mail is ever sent (sending just fails and is logged). `CORS_ALLOW_LOCALHOST=1` lets pages opened on `localhost` call the backend; it is ignored when `NODE_ENV=production`.

Start the database, create the accounts, start the backend (three steps, the first two once):

```powershell
npm run db:start      # starts a local PostgreSQL (data in b2b-backend\.localdb), creates the database, applies the migrations
npm run db:seed       # creates a verified admin, buyer and supplier; prints their e-mails and passwords HERE, once
npm run dev           # the backend on http://localhost:4000 (restarts when you edit the code)
```

`db:seed` prints the passwords in the terminal and also saves them in `b2b-backend\.localdb\accounts.txt` (not in git). Keep the database running between sessions; stop it with `npm run db:stop`.

### 2. The frontend

In a second PowerShell window:

```powershell
cd C:\dev\Biddex-frontend
node tools/serve.js
```

Open <http://localhost:8080> and sign in with one of the seeded accounts. Reload the page to see edits to the files (the server never caches). Another port: `node tools/serve.js 8081` (then set `FRONTEND_URL` accordingly).

### Check that it is the local backend

Open the browser's DevTools → Network: requests go to `http://localhost:4000/api/...`. In the console, `BIDDEX_API` shows the address in use.

### Limits of the local setup

- **No file storage.** Uploading documents and photos answers "File storage is not configured" unless you set the `S3_*` variables for a bucket of your own. Never use the production bucket.
- **No e-mail.** Verification and password-reset links are never delivered; the seeded accounts are already verified. A new account registered in the app stays unverified (set `emailVerified` in the local database if you need it).
- The local database is yours: delete `b2b-backend\.localdb` (after `npm run db:stop`) to start from scratch.

### Stop

`Ctrl+C` in the two windows, then `npm run db:stop` in the backend folder.

## Tests

```powershell
cd C:\dev\Biddex-frontend
Get-ChildItem test\*.test.js | ForEach-Object { node $_.FullName }
```

They are plain Node scripts without dependencies and run in GitHub Actions on every push (`.github/workflows/ci.yml`).

## Rules for changes

- `server-errors.js` is loaded as `server-errors.js?v=N` and `config.js` as `config.js?v=N`: change the file, bump `N` in every page that loads it in the same commit (GitHub Pages caches for 10 minutes).
- The production API address is written in `config.js` only; `test/api-base.test.js` checks it.
- `privacy.html`, `terms.html` and `ar/*` are generated by `tools/build-legal.js` in the **Biddex-landing** repository: do not edit them here.
